### What is MTP?
Multi-Token Prediction, the model predicts draft tokens ahead, then verifies them.
**Zero quality loss** (rejected drafts are regenerated by the full model).
**~1.5-2x throughput** improvement. MTP support merged into mainline llama.cpp on 2026-05-16.

## Server lifecycle

The canonical production settings live in `config/profiles/default.sh`.
All launch paths delegate to `bin/llamactl`, which owns the exact server
PID, waits for health, and rotates logs under `~/.local/state/local-llm/`.

```bash
cd ~/Desktop/local_llm

bin/llamactl start
bin/llamactl status
bin/llamactl health
bin/llamactl logs
bin/llamactl restart
bin/llamactl stop
bin/llamactl command  # validate and print the exact command
```

The interactive `bin/llama-launch` creates an inherited profile under
`~/.local/state/local-llm/` and then delegates to the same controller.

Muse Glimmer is served with current mainline llama.cpp on either ROCm or Vulkan.
Launch it interactively with `llamaserver` -> `ROCm` or `Vulkan` -> model `6`,
or use a conservative 16k profile:

```bash
bin/llamactl restart --profile config/profiles/muse-glimmer-30b-q5km-vulkan-q8-16k.sh
bin/llamactl restart --profile config/profiles/muse-glimmer-30b-q5km-rocm-q8-16k.sh
```

To enable its 15-token DFlash drafter:

```bash
bin/llamactl restart --profile config/profiles/muse-glimmer-30b-q5km-vulkan-q8-16k-dflash.sh
bin/llamactl restart --profile config/profiles/muse-glimmer-30b-q5km-rocm-q8-16k-dflash.sh
```

- API endpoint: `http://127.0.0.1:1234/v1`
- Browser chat UI: `http://127.0.0.1:1234`
- Default exposure: localhost only
- Non-loopback profiles are rejected unless `LLAMA_API_KEY_FILE` is configured

## Manual Server Commands

### Standard (mainline llama.cpp)
```bash
HIP_VISIBLE_DEVICES=0 ~/Desktop/local_llm/llama.cpp/build/bin/llama-server \
  -m ~/Desktop/local_llm/llama_server/models/Qwen3.6-35B-A3B-UD-IQ4_NL.gguf \
  -ngl 99 \
  -c 262144 \
  --parallel 1 \
  --cache-type-k q8_0 \
  --cache-type-v q8_0 \
  --flash-attn on \
  --port 1234 \
  --host 127.0.0.1
```

### Flag reference
| Flag | Why |
|------|-----|
| `HIP_VISIBLE_DEVICES=0` | Forces RX 7900 XTX, without it the iGPU causes a segfault |
| `-ngl 99` | Offload all layers to GPU |
| `-c 262144` | Full 262k native context, fits because only 10/40 layers are standard attention (2 KV heads each); KV cache is ~2.8 GB at q8_0 |
| `--parallel 1` | Server defaults to 4 parallel slots which multiplies KV cache by 4 and exhausts VRAM |
| `--cache-type-k/v q8_0` | Halves KV cache vs f16; needed to free room for compute buffer |
| `--flash-attn on` | Reduces compute buffer size. Note: must pass explicit `on`, bare `-fa` is broken in this build |
| `--ubatch-size 256` | Caps compute buffer during large prefill, prevents VRAM spike OOM at high context. Drop to 128 if still crashing. (`--ubatch` is the wrong flag name and will error) |
| `--spec-type draft-mtp` | Enables MTP speculative decoding (auto-added by launch script for MTP models) |

---

## Context Window, Why 262k Fits on 24 GB

Qwen3.6-35B-A3B is unusual: only 10 of its 40 layers are standard attention.
The other 30 are linear DeltaNet layers with fixed-size state (not per-token KV cache).
The 10 attention layers have only 2 KV heads at 256 dim.

KV cache per token at f16: `2 × 10 × 2 × 256 × 2 bytes = 20 KB/token`
Full 262k context at f16: `~5 GB`, fits in the ~6 GB left after the 18.5 GB model loads.
With q8_0: `~2.8 GB`, leaves enough room for the compute/prefill buffer (804 MB).

## Qwen Code (AI Coding Agent), Primary Harness

Terminal agent optimized for Qwen models. Requires llama-server running on port 1234.

```bash
cd /your/project
qwen
```

Config: `~/.qwen/settings.json`

### Key features vs OpenCode/OpenClaw
- Passes `preserve_thinking: true` every request, model keeps reasoning traces across turns
- Passes Qwen3.6 official sampling params (temp=1.0, top_k=20, presence_penalty=1.5)
- Native thinking mode control per model
- MCP servers: Context7 (docs), GitHub, Brave Search, Filesystem

### Thinking mode by task
| Task type | Model | Temp | Presence penalty |
|-----------|-------|------|------------------|
| Research / general | 35B MoE + MTP | 1.0 | 1.5 |
| Precise coding | 27B Dense | 0.6 | 0.0 |

### MCP servers requiring API keys
- **Brave Search**: https://api.search.brave.com, free tier available (2000 queries/month)
- **GitHub**: https://github.com/settings/tokens, classic PAT, `repo` + `read:org` scopes

## Hermes Agent (self-improving, persistent memory)

Autonomous agent with persistent memory/skills, learning loop, and 90+ bundled skills.
Requires llama-server running on port 1234.

```bash
cd /your/project
hermes
```

Config: `~/.hermes/config.yaml`  
Install: `~/Desktop/hermes-agent-main/` (source, uv venv)  
Binary: `~/.local/bin/hermes` → `~/Desktop/hermes-agent-main/venv/bin/hermes`

### Key features
- **Persistent memory**: saves notes/user profile across sessions (`~/.hermes/` MEMORY.md + USER.md)
- **90 bundled skills**: research, coding, debugging, GitHub PR workflow, arxiv, LLM serving, etc.
- **MCP servers**: Context7 (docs), Filesystem (no API keys needed)
- **Auto-compression**: summarises long contexts at 80% of 262k window
- **max_turns: 60** per session (configurable)
- **Local-first**: no cloud API keys required

### Commands
```bash
hermes                  # Start chat
hermes status           # Check configuration
hermes doctor           # Diagnose issues
hermes --help           # Full command list
```

## Reproducible benchmark matrix

`bin/llama-benchmark` runs isolated servers on port 1235. It never kills
an existing port owner and never overwrites prior results. Each run writes a
timestamped CSV plus one log per configuration under
`output/benchmarks/YYYY-MM-DD_HH-MM-SS/`.

```bash
# Inspect the matrix without loading a model
bin/llama-benchmark --list
bin/llama-benchmark --backend vulkan --filter 'MoE\+MTP' --dry-run

# Run one production-like configuration after stopping the main server
bin/llamactl stop
bin/llama-benchmark \
  --backend vulkan \
  --filter 'MoE\+MTP.*q8_0' \
  --limit 1 \
  --ctx-k 128
```

The benchmark uses server-reported token counts and timings, forces the requested
decode length, uses `--ubatch-size 192`, and records separate short and long
prefill measurements. Full matrix runs remain expensive.

## Known Quirks

- **`ps` shows ~14 GB RSS** for llama-server, this is ROCm mapping VRAM into the
  process's CPU virtual address space. Actual system RAM used is ~3-4 GB (`free -h` confirms).
- **GPU shows 24 GB, sysfs shows 25.75 GB**, same thing, binary (GiB) vs decimal (GB) units.
  `23.98 GiB = 25.75 GB`. No hidden VRAM.
- **`-fa` flag broken**, always use `--flash-attn on` explicitly.
- **iGPU segfault**, ROCm profiles set `HIP_VISIBLE_DEVICES=0`; Vulkan profiles
  explicitly select `Vulkan0`.
